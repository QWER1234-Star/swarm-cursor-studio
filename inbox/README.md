## 任务 A：让不同模型写页面结构（最优先）

**目的**：验证我这份提示词对不同模型、不同行业是否稳健，同时收集真实样本做兼容性测试。

**做法**：把下面这段整段复制给任意 AI（DeepSeek / Kimi / 豆包 / 通义 / Claude / ChatGPT 网页版都行，不需要 API Key），把最后的「需求」换成不同行业。

```
你在为一个「多光标施工动画」写网页结构：一群光标会照着你写的 HTML 把页面一块块画出来。

只输出 HTML 片段：不要 <html>/<body>/<style>，不要写任何 CSS，不要解释，不要 markdown 围栏。
只用这些标签：div section span p h1 h2 h3 a ul li em strong br

可用 class（只能用这些，不要自创）：
布局：wrap、section
导航：nav、brand、nav-links
首屏（三选一）：hero（左文右图两列）、hero-center（居中单列）、hero-full（整屏大图+遮罩文字）；配套 hero-copy、eyebrow、h1、lead、btn、btn-primary、btn-ghost、btn-row
区块：features、quote、pricing、stats、cta、footer
网格：grid-2、grid-3、grid-4
卡片：card、card-plain、plan（可选 hot）、tier、price
图片位：media、media-wide、media-tall（只写空 div，不要 src）
文字：h2（区块标题）、h3（卡片标题）、lead（说明）、lead-sm、muted、stat-num、stat-label、section-head（可选 ctr）、contact-line、foot-links

规则：
1) 图片一律写成空的 <div class="media"></div>（宽幅用 media-wide，竖图用 media-tall）。不要写 src，不要写 style，程序会配真实照片。
2) 需要点击的元素加 data-action="wechat|tel|mailto|link"，需要值时加 data-value="..."。
3) 文案必须是真实可用的中文：写出具体的卖点、数字、地址、时间、价格，不要「标题一」「示例文本」「lorem」。
4) 不要写 style 属性，不要写行内颜色，样式全部由 class 决定。
5) 首屏从 hero（左文右图）、hero-center（居中）、hero-full（整屏大图）三选一，自己判断哪个最适合这个行业。
6) 整页 4~6 个区块，块与块之间要有节奏变化。
7) 不同行业的页面结构应该明显不同：门店类偏「首屏图 + 服务卡片 + 地址时间」，活动类偏「大图 + 讲者/日程 + 报名」，个人类偏「居中介绍 + 作品网格」，产品类偏「功能网格 + 数据 + 价格」。不要每次都套同一个顺序。
8) 三个卡片的文案要具体且彼此不同，不要三句话一个意思。

需求：做一个高端美甲店的预约页
```

**建议跑的组合**（10 份就够，别贪多）：

| 行业（替换上面最后一句） | 建议模型 |
|---|---|
| 做一个高端美甲店的预约页 | DeepSeek |
| 做一个 AI 写作工具的落地页 | DeepSeek |
| 做一个社区瑜伽课的招生页 | Kimi |
| 做一个独立摄影师的个人主页 | Kimi |
| 做一个精品咖啡店的官网 | 豆包 |
| 做一个少儿编程课的招生页 | 豆包 |
| 同一句「美甲店」再跑一次（换模型或换会话） | 通义 |
| 同一句「美甲店」第三次 | Claude / ChatGPT |
| 做一个宠物殡葬服务的介绍页（冷门行业） | 任意 |
| 做一个工业设备租赁的公司页（B 端） | 任意 |

**存法**：一个行业一个文件，命名 `行业.html`，例如 `美甲-DeepSeek.html`、`AI写作-Kimi.html`。

**验收（你贴之前自己看一眼，不合格就重跑）**：
- 文件以 `<` 开头，没有 ```` ``` ```` 围栏，没有 `<style`、没有 `style=`
- class 只用了清单里的名字（模型爱自创 `hero-title`、`container`、`section-title` 这类）
- 没有 `<img src=...>` 外链图

不合格的直接标 `.bad` 后缀一起给我，**这些反例比合格样本更有用**——我能据此加固提示词。

## 任务 B：攒 20 条真实的小微生意需求

**目的**：批量跑测试 + 扩充内置场景。我要用它验「不同行业的页面结构真的不一样」，这是 P2 的核心验收指标。

**格式**：一个 `需求.csv`，三列，无表头说明也能读懂：

```csv
一句话需求,品牌/店名,联系方式
做一个老小区里的修鞋铺的小程序落地页,老张修鞋,微信 laozhang123
```

**怎么攒**：不用自己想，去小红书/抖音/大众点评搜「同城」类目，挑 20 个真实存在的小店；或者直接让 AI 生成 20 条（但要像真的，有具体地址和营业时间）。

**要覆盖的冷门行业**（这些最能暴露模板化问题）：修鞋、开锁、宠物殡葬、月嫂、拆迁回收、麻将馆、钓具店、书法班、口腔诊所、搬家公司、婚庆、二手车、代账、保险经纪。

## 任务 C：给我 3–5 个你觉得「好看」的网站

**目的**：现在排版质量由我写的 CSS 决定，上限就是我的审美。你给我参考，我把它们拆成设计 token（配色、字号阶梯、间距、圆角、卡片质感），直接改进那套 CSS。

**存法**：`C-参考/` 下每个站一个文件夹，放整页截图（F12 → 截屏整个页面，或滚动拼接），加一个 `说明.txt`：

```
喜欢什么：首屏的留白很大，标题特别粗，配色只有黑+一个荧光绿，卡片没有边框只有一层很淡的阴影
不喜欢什么：按钮是圆角的，我想要方角
```

**别给**：模板站、企业官网那种"新闻中心 + 关于我们"的结构。我要的是落地页。

## 合并流程

1. 你把文件放进对应目录
2. 跟我说「A 放好了」（或 B / C）
3. 我做：批量编译 → 出结构对比报告（块数、首屏类型、区块顺序）→ 标出编译失败的样本 → 修提示词或加兼容 → 把好的样本转成项目内的回归用例
